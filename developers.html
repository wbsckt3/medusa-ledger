Developer guide

The OSS demo does not simulate a commercial tenant. It shows one fundamental thing: how a system turns a business fact into verifiable, immutable evidence.

You define the event. Medusa makes it verifiable.

Contents 1. What is an event? 2. Docker demo 3. See the chain 4. Detect tampering 5. Any domain 6. Core vs Cloud

1. What is an event?

An event is a fact that happened in a system and that you want to prove later was recorded exactly as stored. Medusa does not need to know what the event means.

EVENT │ ├── eventId ├── eventType ├── timestamp ├── payload └── metadata ↓ HASH SHA-256 ↓ BLOCK ↓ CHAIN

Medusa is not your business. Medusa says: this fact was registered this way, at this time, and the evidence was not altered.

2. Docker demo (no TukTuk, no ePayco, no ERP)

git clone https://github.com/wbsckt3/medusa-ledger.git
cd medusa-ledger
docker compose up --build
curl -X POST http://localhost:8080/api/events \
  -H "Content-Type: application/json" \
  -d '{
    "eventId": "order-001",
    "eventType": "ORDER_CREATED",
    "payload": {
      "customerId": "customer-42",
      "amount": 50000,
      "currency": "COP"
    }
  }'
curl -X POST http://localhost:8080/api/events \
  -H "Content-Type: application/json" \
  -d '{
    "eventId": "payment-001",
    "eventType": "PAYMENT_RECEIVED",
    "payload": {
      "orderId": "order-001",
      "amount": 50000,
      "currency": "COP"
    }
  }'
curl http://localhost:8080/api/verify

Magic moment: {"valid":true,"message":"Ledger integrity verified"}

CLI alternative:

node bin/medusa.js event create --type ORDER_CREATED --id order-002 --amount 12000
node bin/medusa.js ledger verify
node bin/medusa.js ledger show

3. See the chain

curl http://localhost:8080/api/ledger/show
YOUR APPLICATION │ "Something happened" ▼ MEDUSA CORE │ ├── event ├── timestamp ├── payload ▼ SHA-256 → BLOCK → LEDGER → VERIFY

4. Detect tampering

If someone changes a stored amount from 50000 to 90000, the block hash no longer matches. /api/verify returns valid: false with reason Hash mismatch. That is the second magic moment: not “I have blockchain”, but “I can detect that history was altered”.

5. Same Core, many domains

  • E-commerce: ORDER_CREATED, PAYMENT_RECEIVED, REFUND_CREATED
  • Logistics: PACKAGE_DISPATCHED, PACKAGE_DELIVERED
  • HR: CONTRACT_SIGNED, SALARY_PAID
  • SaaS: SUBSCRIPTION_CREATED, SUBSCRIPTION_CANCELLED
  • IoT: SENSOR_READING, DEVICE_MAINTENANCE

Medusa does not need to know any of those domains. That is the value of the Core.
